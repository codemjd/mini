# المعمارية المستهدفة

## المبدأ الأساسي: ملف مشروع واحد، عدة واجهات تنفيذ

الواجهة، والمعاينة، وعامل التصيير، وأدوات الوكيل الآلي تقرأ وتعدّل صيغة مشروع واحدة ذات إصدار واضح. لا نسمح بوجود نسخة بيانات مستقلة للمحرر ونسخة أخرى للمحرك.

## الطبقات

### 1. تطبيق الويب

مسؤول عن:
- لوحة المشاريع وعمليات الإنشاء والاستيراد والتصدير.
- محرر المشاهد والطبقات والنصوص والتوقيت.
- معاينة فورية للمشهد الحالي.
- واجهة هاتف RTL مع أزرار واضحة ومساحات لمس مناسبة.
- الحفظ المحلي التلقائي في IndexedDB.
- إظهار حالة كل مهمة تصيير ونتيجة التحقق.

لا ينفذ التطبيق تصييرًا طويلًا داخل واجهة الهاتف.

### 2. نموذج المشروع

كل مشروع له:
- `schemaVersion` للتحقق من توافق الإصدارات.
- `projectId` ومعرّف وعنوان ووصف وإعدادات عامة.
- `format`: أبعاد الفيديو، FPS، نسبة العرض، خلفية، لغة.
- `scenes[]`: ترتيب المشاهد ومدتها.
- `tracks[]`: narration وsound effects وvisual layers.
- `assets[]`: مصدر الأصل، نوعه، ترخيصه، وبيانات فحصه.
- `sources[]`: المراجع المستخدمة في البحث والسيناريو، إن وجدت.
- `renderProfile`: إعدادات draft/final.
- سجل تغييرات/بيانات وصفية عند الحاجة.

كل توقيت يحفظ بوحدة Frames أو milliseconds بطريقة موحدة، مع قاعدة واضحة للتحويل. لا نخزن توقيتات متعارضة بين المقاطع.

### 3. محرك المشاهد

- كل Scene هو React composition مستقل قابل لإعادة الاستخدام.
- الرسوم تفضّل SVG وعناصر vector والنصوص.
- الحركة تعتمد إطارات محددة deterministic frame-based animation.
- الكاميرا الافتراضية هي حركة موضع/حجم على مساحة المشهد: zoom, pan, crop.
- كل عنصر مرئي له حدود زمنية وطبقات واضحة.
- خطوط عربية مضمّنة أو محلية مرخصة، مع اختبار تشكيل واتجاه RTL.
- معاينة Player تعيد استخدام composition نفسها التي يستعملها التصدير.

### 4. طبقة التحكم الآلي

هذه الطبقة أساسية كي يستطيع الوكيل استخدام التطبيق، وليست ميزة لاحقة.

واجهة الأوامر المقترحة (الأسماء وصفية وليست منفذة بعد):

- `project.create`
- `project.open`
- `project.validate`
- `scene.add`
- `scene.update`
- `scene.reorder`
- `scene.remove`
- `asset.attach`
- `narration.generate`
- `render.start`
- `render.status`
- `render.inspect`
- `render.download`

كل أمر يستقبل مدخلات typed ويعيد نتيجة structured تتضمن success/error، وIDs، ورسائل تحقق. الواجهة المرئية تستخدم نفس طبقة الأوامر بدل وجود منطق خاص بها لا يمكن للوكيل استدعاؤه.

### 5. عامل التصيير

دورة المهمة:
1. استلام مشروع محدد الإصدار ومعرّف المهمة.
2. التحقق من schema والموارد والأصول وسياسة المحتوى.
3. إعداد bundle للمشاهد.
4. تصيير الفيديو بإعداد draft أو final.
5. تجميع/ترميز الصوت والصورة عند الحاجة.
6. فحص الناتج باستخدام أدوات مثل FFprobe وقراءة metadata.
7. نشر artifact قصير الأجل وإرجاع مرجع المهمة والناتج.
8. تنظيف الملفات المؤقتة.

يجب أن تكون المهمة قابلة لإعادة التشغيل، وأن تُسجل الأخطاء. لا نعيد تشغيل تصيير مكتمل بلا داعٍ.

### 6. فحص المحتوى والجودة

قواعد آلية:
- منع نوع مسار صوتي باسم music.
- السماح بأنواع narration وnon-musical SFX فقط.
- رفض أي asset لم يسجل مصدره وترخيصه.
- فحص مدد المقاطع وتداخلاتها وملاءمة الصوت.
- فحص metadata للـMP4.

قواعد تتطلب فحصًا بصريًا:
- عدم وجود بشر أو حيوانات أو شخصيات حية.
- عدم وجود نغمات أو موسيقى ضمن المؤثرات.
- سلامة الخط العربي والتكوين البصري.
- عدم وجود عناصر مقصوصة أو وميض أو انتقالات غير مقصودة.

## فصل البيانات العامة والخاصة

المستودع الحالي عام:
- ينشر الكود والوثائق العامة فقط.
- لا يرفع إليه ملف مشروع خاص أو سيناريو المستخدم أو TTS keys أو ملفات فيديو خاصة.
- تحفظ بيانات المشاريع محليًا افتراضيًا.
- أي عامل تصيير عام تجريبي لا يستقبل موضوعًا حساسًا أو غير عام.
- قبل إنتاج فيديو خاص عبر خدمة سحابية، نحتاج تخزينًا/عاملًا خاصًا وآلية مصادقة وأسرار آمنة.

## تصميم قابل للتوسع

نبدأ محليًا بدون حسابات:
- PWA + IndexedDB.
- صيغة مشروع JSON قابلة للاستيراد والتصدير.
- مكتبة مشاهد مدمجة.
- أوامر تحكم محلية موثقة.
- عامل تصيير تجريبي بمادة غير خاصة.

لاحقًا:
- خدمة مهام خاصة ومصادقة.
- تخزين أصول خاص.
- TTS provider adapter.
- قائمة مهام ومراجعة وتصدير متكرر.
- معالجة الفيديو على أجزاء عند الحاجة إلى إنتاج طويل.

## تعريف النجاح

يمكن للوكيل، دون نقر يدوي في الواجهة:
1. إنشاء مشروع من JSON.
2. تعديل مشهد وإعادة تحميل المشروع.
3. معاينة نفس التركيبة التي سيستخدمها التصدير.
4. بدء مهمة تصيير وتتبعها.
5. استلام MP4 وفحصه.
6. الإبلاغ بصدق عن أي فشل مع سجل قابل للتشخيص.
