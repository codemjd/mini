# ورشة الشرارات Mini — النسخة الأولى / المسار B: الاستقلالية القصوى

الحالة: مسار تجريبي مستقل للمقارنة، وليس اعتمادًا نهائيًا.

## الهدف
تقليل الاعتماد على محركات الألعاب ومكتبات التشغيل، وبناء معظم سلوك المحرك داخل Spark Core. هذا المسار يمنحنا سيطرة أكبر لكنه الأبطأ والأعلى مخاطرة.

## المعمارية
- Spark Core مملوك بالكامل: دورة التشغيل، المشاهد، الكائنات، المكونات، الأحداث، الكاميرا، الإدخال، إدارة الأصول.
- Renderer: Canvas 2D API مباشرة في البداية، مع واجهة تسمح بإضافة WebGL لاحقًا.
- Physics: مصادمات AABB ودوائر وحركة أساسية مملوكة لشرارات؛ لا ندّعي محاكاة Box2D كاملة.
- Audio: Web Audio API خلف Audio Adapter.
- Visual Logic: محرر عقد وEvent Graph خاصان بشرارات، على مراحل.
- Storage: IndexedDB.
- Export: Runtime صغير مستقل يقرأ صيغة Spark Project.

## قواعد الاستقلال
1. لا Phaser ولا PixiJS ولا محرك ألعاب خارجي في مسار التشغيل الأساسي.
2. يمكن استخدام أدوات تطوير واختبار مساعدة، لكن لا تتحول إلى تنسيق ملفات أو واجهات عامة ملزمة.
3. تعريف صيغة المشروع وعقود المكونات ملك لشرارات.
4. لا نبني فيزياء متقدمة أو محرر عقد كاملًا قبل إثبات الحاجة.

## نطاق النسخة الأولى
- مشهد واحد وكائنات Sprite/Shape.
- رسم وتحويلات وتحديد وسحب.
- إدخال لمس ولوحة مفاتيح.
- تصادمات بسيطة محدودة ومعلنة.
- حفظ وفتح مشروع.
- معاينة أساسية.
- لا خرائط ضخمة ولا إضاءة متقدمة ولا محرر عقد شامل في هذه المرحلة.

## مراحل التنفيذ
1. توثيق نموذج المشروع ودورة حياة الكائن.
2. بناء Canvas Renderer صغير مع اختبارات للرسم والتحويل.
3. بناء Scene Graph وComponent System.
4. بناء إدخال موحد وإدارة توقيت الإطارات.
5. بناء تصادمات أولية واختبارات حالات الحواف.
6. بناء التخزين والاستيراد والتصدير.
7. قياس الأداء على هاتف Android متوسط/ضعيف.
8. مقارنة تكلفة تطوير كل ميزة بالمسار A.

## بوابات القبول
- رسم 500 كائن بسيط في مشهد اختبار دون انهيار.
- ثبات تحديث الحركة والتصادم ضمن حدود الأداء المتفق عليها.
- عدم فقدان بيانات المشروع عند الحفظ وإعادة الفتح.
- اختبارات التحويلات والتصادمات وتوقيت الإطارات.
- توثيق الميزات غير المدعومة بدل إخفاء القيود.

## المخاطر
- إعادة اختراع حلول موجودة وإهدار الوقت.
- Canvas 2D قد يحد من المؤثرات والأداء في المشاهد الكبيرة.
- بناء محرر عقد وفيزياء متقدمة سيضاعف المدة.
- صعوبة الوصول إلى جودة محرك ناضج بفريق صغير.

## قرار هذا المسار
يُستخدم كمرجع للاستقلالية ولتحديد ما يجب أن نملكه داخل Spark Core. لا يُختار كاملًا إلا إذا أثبتت القياسات أن كلفته مقبولة.
