# المرحلة صفر — نموذج البيانات ونظام التعلم والتخزين
## المواصفات التنفيذية الأولية — 0.1

هذه الوثيقة تحوّل اتجاه «مصنع الألعاب دون AI توليدي» إلى نماذج بيانات قابلة للتنفيذ. النماذج أدناه مقترحة للمرحلة الأولى، ويجب تثبيت أسمائها وحدودها عبر اختبارات قبل اعتمادها نهائيًا.

---

## 1. مبادئ البنية

1. **البيانات هي المصدر الأساسي:** المحرر والمعاينة والتصدير تقرأ وثيقة المشروع نفسها.
2. **لا منطق برمجي حر:** الأنظمة الرسمية تعمل بمكوّنات وأنواع أحداث وشروط وإجراءات مسموح بها.
3. **المحرر مستقل عن التشغيل:** لا يتغير المشروع الأصلي بسبب تشغيل المعاينة.
4. **كل مورد له هوية وإصدار:** المشهد والمكوّن والسلوك والأصل والدرس.
5. **التركيب قابل للتحقق:** لا يُسمح بربط مكوّن أو إجراء غير متوافق.
6. **Mobile-first:** كل عملية أساسية قابلة للإنجاز باللمس، دون الاعتماد على السحب الدقيق وحده.
7. **البيانات قابلة للترحيل:** أي تغيير في بنية المشروع يجب أن يملك ترحيلًا واختبارًا.

## 2. وثيقة المشروع المقترحة

~~~json
{
  "format": "spark-project",
  "schemaVersion": 1,
  "id": "project-id",
  "metadata": {
    "name": "My Game",
    "createdAt": "ISO-8601",
    "updatedAt": "ISO-8601"
  },
  "settings": {
    "orientation": "landscape",
    "targetFps": 60,
    "inputProfiles": ["touch", "keyboard"]
  },
  "sceneOrder": ["scene-main"],
  "scenes": [],
  "assetReferences": [],
  "prefabReferences": [],
  "buildProfiles": []
}
~~~

هذه وثيقة توضيحية وليست عقدًا نهائيًا. يجب ألّا تُخزّن فيها الملفات الثنائية الكبيرة؛ تخزّن فيها مراجع الأصول وبياناتها الوصفية، بينما تحفظ ملفات الصور والصوت في مخزن الأصول.

## 3. المشهد والكائن

### المشهد

يحتوي المشهد على:
- معرف واسم.
- أبعاد وخلفية.
- الطبقات وترتيب الرسم.
- الكاميرا وحدودها.
- قائمة الكائنات.
- قواعد اللعب أو مخطط المنطق.
- انتقالات الدخول والخروج إن وجدت.

### الكائن

الكائن تعريف بيانات، وليس عنصر DOM أو كائن Canvas مباشرًا. يحتوي على:
- معرف فريد.
- اسم.
- قائمة مكوّنات.
- نسخ من سلوكيات المكتبة.
- Transform: الموقع والحجم والدوران والطبقة.

يجب أن يكون لكل كائن مكوّن Transform واحد فقط، وألا يسمح بوجود مكوّنات متعارضة أو قيم خارج الحدود.

## 4. سجل المكوّنات

لكل مكوّن تعريف مركزي يحتوي على:
- معرف نوع ثابت.
- رقم إصدار المخطط.
- وصف عربي وأيقونة وتصنيف.
- الخصائص وأنواعها والحدود والقيم الافتراضية.
- المكوّنات المتوافقة أو المتعارضة.
- المحرر المناسب لكل خاصية.
- اختبار تحقق.
- كود التشغيل المقابل داخل Spark Runtime.

### المكوّنات الأساسية المقترحة

| المجموعة | المكوّنات |
|---|---|
| أساسية | Transform, Visual, Layer |
| رسوم | Sprite, Animation, Particles |
| حركة | Movement, PlatformMovement, Input |
| تصادم | Collider, PhysicsBody |
| شخصية | Health, Damage, Combat, Inventory |
| سلوك | Patrol, Follow, Guard, Flee, RangedAttack |
| عالم | Collectible, Door, Trigger, Checkpoint |
| صوت | AudioEmitter, MusicZone |
| واجهة | UIWidget, ButtonAction, HUDValue |
| كاميرا | CameraTarget, CameraBounds |

لا نحتاج إلى بناء كل المكوّنات في أول إصدار. يبدأ التنفيذ بمجموعة صغيرة تغطي قالب لعبة كاملًا، ثم تضاف المجموعات حسب نتائج الاختبار.

## 5. السلوكيات والقواعد

السلوك وحدة قابلة للإضافة، لها تعريف ثابت ومعاملات محددة. مثال:

~~~json
{
  "id": "behavior-guard-01",
  "definitionId": "enemy.guard",
  "version": 1,
  "parameters": {
    "radius": 180,
    "returnToStart": true,
    "attackOnSight": false
  }
}
~~~

قواعد اللعب تكون بصيغة:

~~~json
{
  "id": "rule-open-gate",
  "event": { "type": "item.collected", "itemId": "key-blue" },
  "conditions": [
    { "type": "counter.atLeast", "counterId": "blue-keys", "value": 3 }
  ],
  "actions": [
    { "type": "object.setEnabled", "targetId": "gate-blue", "value": false },
    { "type": "ui.showMessage", "text": "فُتحت البوابة!" }
  ]
}
~~~

### قواعد السلامة والتنفيذ

- الأحداث والشروط والإجراءات من سجل مسموح فقط.
- كل خاصية مرتبطة بنوع معروف وحدود واضحة.
- لا eval ولا تنفيذ JavaScript نصي ولا تحميل وحدات غير موثوقة.
- كل قاعدة قابلة للتعطيل والنسخ والحذف.
- يجب اكتشاف الإجراء الذي يستهدف كائنًا غير موجود قبل تشغيل اللعبة.
- محرر العقد المتقدم واجهة تحرير؛ أما التشغيل فيحوّل المخطط إلى تعليمات تشغيل حتمية قابلة للاختبار.

## 6. القوالب والتركيبات

- **Template:** مشروع ابتدائي متكامل بنظام لعب ومشاهد وواجهة وأصول أساسية.
- **Prefab:** كائن أو مجموعة كائنات قابلة لإعادة الاستخدام، مثل باب ومفتاح أو صندوق.
- **System Pack:** مجموعة مكوّنات وقواعد وسلوكيات متوافقة، مثل حزمة حياة وقتال.
- **Asset Pack:** صور وأصوات وخطوط ورسوم مع بيانات الحقوق والترخيص.

يجب أن تعرض شاشة كل حزمة توافقها، وما إذا كانت تحتاج إلى مكوّنات أخرى، وحجمها، وترخيصها.

## 7. نظام الدروس التفاعلية

الدرس تعريف بيانات، لا صفحة مكتوبة يدويًا. المثال التالي يشرح الشكل، وليس API نهائيًا:

~~~json
{
  "id": "basics.add-player",
  "title": "أضف شخصية اللاعب",
  "track": "getting-started",
  "level": "beginner",
  "prerequisites": [],
  "practiceTemplate": "lesson-empty-scene",
  "steps": [
    {
      "type": "highlight-tool",
      "target": "asset-library.characters",
      "instruction": "افتح مكتبة الشخصيات."
    },
    {
      "type": "user-action",
      "instruction": "أضف شخصية اللاعب إلى منتصف المشهد.",
      "verify": {
        "type": "project.hasComponent",
        "component": "Transform",
        "objectKind": "hero"
      },
      "hints": [
        "ابحث عن فئة الشخصيات.",
        "اختر شخصية اللاعب ثم اضغط إضافة."
      ]
    },
    {
      "type": "challenge",
      "instruction": "حرّك اللاعب إلى الجهة اليسرى."
    }
  ],
  "completion": {
    "type": "project.objectCountAtLeast",
    "kind": "hero",
    "value": 1
  }
}
~~~

### أنواع خطوات الدرس المسموحة

- intro: تمهيد وهدف.
- highlight-tool: إبراز أداة أو منطقة.
- guided-action: إرشاد المستخدم إلى إجراء.
- user-action: ينجز المتعلم خطوة بنفسه.
- verify: فحص حالة المشروع.
- quiz: سؤال قصير مع تصحيح فوري.
- preview: تشغيل اللعبة التدريبية.
- challenge: تحدٍّ دون حل مباشر.
- summary: مراجعة ما تعلّمه.

### متطلبات جودة الدرس

- لا يتقدم الدرس حتى يتحقق الشرط، إلا إذا اختار المستخدم تخطيه.
- التلميحات تدريجية ولا تكشف الحل فورًا.
- يمكن إعادة الخطوة أو إعادة الدرس من نقطة بداية آمنة.
- لا تعدّل الدروس مشروع المستخدم الحقيقي دون موافقته؛ تبدأ داخل مشروع تدريب مستقل أو نسخة قابلة للاستعادة.
- يشرح الدرس سبب الخطأ، لا يكتفي برسالة «خطأ».
- كل درس يحتوي معيار نجاح قابلًا للفحص، وليس مجرد مشاهدة.
- تظل النصوص والشرح والأمثلة متاحة دون اتصال بعد تنزيل حزمة الدروس.
- حفظ التقدم منفصل عن حفظ مشروع اللعبة.

## 8. تخطيط الأكاديمية

عدد الدروس المستهدف 100 أو أكثر، مع 30 درسًا مكتملًا على الأقل في أول إصدار تعليمي عام.

| الوحدة | أهداف التعلم |
|---|---|
| أساسيات الورشة | إنشاء مشروع، فتحه، حفظه، التراجع، النسخ |
| المشاهد | إنشاء المشاهد وتسميتها وترتيب الانتقالات |
| الأصول | البحث والاستيراد والتصنيف والتحقق من الحقوق |
| الشخصيات | إضافة الشخصية والخصائص والحركة والتحريك |
| الخرائط | الخلفيات والطبقات والعوائق والكاميرا |
| التصادم | الأجسام والمناطق والمحفزات |
| المنطق | الأحداث والشروط والإجراءات والعدادات |
| الأعداء | الحراسة والدورية والمطاردة والهجوم والتراجع |
| أنظمة اللعب | الصحة والضرر والجمع والمخزون والمكافآت |
| الواجهات | الشاشة الرئيسية والتوقف والإعدادات وHUD |
| المؤثرات | الصوت والاهتزاز والجسيمات والانتقالات |
| الإتقان | الاختبارات والأداء والتوافق والتصدير |

يجب أن يعلّم كل مسار إنتاج شيء قابل للعب، وأن ينتهي المسار بمشروع صغير يمكن حفظه ومشاركته.

## 9. واجهة الدروس على الهاتف

- مساحة المعاينة تبقى ظاهرة قدر الإمكان.
- بطاقة تعليمات قصيرة فوق المحرر أو أسفله.
- زر واضح للخطوة التالية، وزر للتلميح، وزر لإعادة الخطوة.
- تمييز بصري للأداة المطلوبة.
- عند صغر الشاشة، تُعرض خصائص الكائن في لوحة سفلية قابلة للسحب، وليس في عمود ضيق.
- الأزرار المهمة لها مساحة لمس مناسبة، ولا يعتمد أي درس على السحب الدقيق وحده.
- يمكن إخفاء الشرح مؤقتًا لرؤية اللعبة، ثم استعادته دون فقد التقدم.

## 10. تخزين المشروع والتقدم

### المبدأ

الورشة Local-first: التعديل والحفظ الأساسيان على الجهاز، ولا تحتاج الحسابات أو الخادم كي تعمل الوظائف الأساسية.

### طبقات التخزين المقترحة

- **IndexedDB:** مشاريع المستخدم، وثائق المشاهد، الأصول المستوردة، سجل التعديلات، وتقدم الدروس.
- **Cache Storage / Service Worker:** ملفات التطبيق وحزم الدروس والأصول الافتراضية الضرورية للعمل دون اتصال.
- **ملف مشروع قابل للنقل:** حزمة ZIP منظمة تشمل وثيقة المشروع والأصول المرخصة وملف تعريف الإصدارات.
- **نسخ احتياطي:** تصدير واستيراد يدوي، مع تنبيه المستخدم عند استيراد نسخة تستبدل مشروعًا قائمًا.

### قواعد حماية البيانات

- الحفظ التلقائي بعد فترة قصيرة من توقف التعديل.
- لا يُستبدل آخر حفظ صالح ببيانات تالفة.
- تحقق من المساحة والأخطاء، مع رسالة عربية مفهومة.
- عند الترقية بين إصدارات المشروع، ينشأ مسار ترحيل قابل للاختبار.
- لا يُخزّن تقدم الأكاديمية داخل ملفات الألعاب نفسها.
- لا تعتمد سلامة المشروع على بقاء ذاكرة المتصفح أو بقاء التطبيق مفتوحًا.

**تنبيه:** هذه مواصفات مستهدفة؛ لا تدل على أن كل طبقات PWA وIndexedDB وملف ZIP منفذة حاليًا في المستودع.

## 11. معايير الاختبار

### اختبارات وثيقة المشروع
- إنشاء مشروع وحفظه وإعادة فتحه دون فقد.
- استيراد ملف صحيح ورفض ملف تالف بأمان.
- ترحيل نسخة قديمة إلى مخطط أحدث.
- منع المعرفات المكررة والمراجع المفقودة.

### اختبارات المكوّنات والقواعد
- إضافة المكوّن وضبطه وحذفه.
- رفض قيمة خارج الحدود.
- اكتشاف مكوّنات متعارضة.
- تشغيل قاعدة معروفة والتحقق من النتيجة.
- عدم تغير بيانات التحرير عند تشغيل المعاينة أو إيقافها.

### اختبارات الدروس
- لا يجتاز المستخدم الخطوة قبل تحقيق شرطها.
- التلميح يغير محتوى الإرشاد ولا يغير المشروع.
- إغلاق التطبيق وإعادة فتحه يعيد تقدم الدرس.
- إعادة الدرس تستعيد مشروع التدريب فقط.
- يمكن إكمال الدرس باللمس.

### اختبارات الهاتف
- فتح الورشة على شاشة ضيقة وفي الوضع الأفقي.
- تعديل كائن دون انزلاق الصفحة بدل الساحة.
- فتح لوحة الخصائص وإغلاقها.
- اختبار حفظ المشروع أثناء تبديل التطبيق ثم العودة.
- اختبار اللعب والمعاينة وإيقافهما.

## 12. ما يجب اعتماده قبل المرحلة الأولى

- تثبيت المخطط النهائي لأول مجموعة مكوّنات.
- تثبيت قائمة أول 10 أحداث و20 شرطًا و30 إجراءً أو تعديلها بحسب الاختبار.
- تثبيت صيغة ملف المشروع وإصداره الأول.
- تثبيت صيغة تعريف الدرس وأول درس تدريبي.
- تحديد قالب واحد نستخدمه لاختبار جميع الأنظمة الأولية.
- كتابة اختبارات قبول قابلة للتشغيل قبل توسيع المكتبة.
