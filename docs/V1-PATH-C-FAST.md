# ورشة الشرارات Mini — النسخة الأولى / المسار C: الإنجاز الأسرع

الحالة: مسار تجريبي مستقل للمقارنة، وليس اعتمادًا نهائيًا.

## الهدف
الوصول إلى محرر قابل للاستخدام بسرعة عبر الاستفادة من Runtime جاهز، مع إبقاء ملفات المستخدمين وصيغة المشروع تحت ملكية شرارات. هذا المسار يفضّل سرعة ظهور نتيجة عملية على الاستقلال الكامل في التشغيل.

## المعمارية المرشحة
- Runtime: تقييم Excalibur.js كنواة تشغيل 2D جاهزة بدل كتابة دورة تشغيل ورسم وفيزياء من الصفر.
- Editor: واجهة شرارات الحالية، مع فصلها تدريجيًا عن Phaser.
- Visual Logic: نظام أحداث بسيط خاص بشرارات أولًا؛ يمكن اختبار Rete.js كواجهة تحرير فقط.
- Project Model: Spark Project Schema خاص، مع طبقة تحويل من وإلى Runtime.
- Assets: مدير أصول بسيط واستيراد صور وصوت وخرائط.
- Storage: IndexedDB.
- Export: HTML5/ZIP أولًا؛ Android لاحقًا بعد التحقق من توافق Runtime مع Capacitor.

## قواعد هذا المسار
1. لا نسمح للـ Runtime الجاهز بتحديد صيغة مشروع المستخدم النهائية.
2. كل اتصال بالـ Runtime يمر عبر Engine Adapter.
3. نتحقق من الترخيص والصيانة والتوافق مع الهاتف قبل تثبيت أي اعتماد.
4. لا نضيف مكتبات متعددة تؤدي الوظيفة نفسها.
5. لا نزيل Phaser من main؛ هذا المسار يختبر بديلًا على فرع مستقل.

## نطاق النسخة الأولى
- محرر مشهد واحد.
- كائنات وصور وخصائص وتحريك.
- تشغيل/إيقاف ومعاينة لعب.
- تصادمات أساسية وفق قدرات Runtime المختار.
- حفظ وفتح وتصدير مشروع.
- واجهة عربية RTL مناسبة للهاتف.

## مراحل التنفيذ
1. نموذج تقني صغير يقارن Excalibur مع احتياجاتنا الفعلية.
2. اختبار عرض Sprite وتحريك وتصادم وإدخال لمس.
3. اختبار تحميل الأصول وإعادة تشغيل المشهد.
4. إنشاء Engine Adapter وSpark Project Schema.
5. توصيل المحرر الحالي بالنموذج عبر Adapter.
6. اختبار الأداء وحجم الحزمة على الهاتف.
7. تقييم HTML5/ZIP ثم جدوى Android.

## بوابات القبول
- كل الوظائف الأساسية تعمل من خلال Adapter.
- لا تتسرب أنواع Runtime إلى ملفات المشروع المحفوظة.
- يمكن تصدير مشروع وإعادة فتحه دون فقدان الخصائص.
- build وtypecheck والاختبارات ناجحة.
- تجربة الهاتف أفضل أو أسرع بوضوح من المسار A.

## المخاطر
- الارتباط بتصميم Runtime خارجي وحدوده.
- اختلاف قدرات Runtime عن احتياجات محرر عام لجميع أنواع ألعاب 2D.
- الحاجة إلى طبقة تحويل وصيانة توافق مع كل تحديث.
- قد تكون سرعة البداية على حساب مرونة الأنظمة لاحقًا.

## قرار هذا المسار
هو خط أساس لقياس سرعة الإنجاز. إذا لم يحقق اختصارًا ملموسًا في الوقت دون التضحية بصيغة شرارات، فلا مبرر لاختياره.
