# تنفيذ سجل المكونات — المرحلة الأولى

الحالة: تنفيذ أولي محفوظ على فرع العمل، ولم يُعلن جاهزًا للإنتاج قبل تشغيل الاختبارات.

## ما أُضيف

- سجل مركزي في `src/engine/component-registry.ts` يعرّف 12 مكوّنًا:
  Transform, Visual, Animation, Collider, Movement, Player Input, Health, Combat, Collectible, Enemy Brain, Trigger Zone, Audio Emitter.
- لكل مكوّن اسم عربي ووصف وفئة وأنواع كائنات متوافقة وخصائص افتراضية.
- تحقق مركزي من النوع والنطاق والخيارات واللون وطول النص.
- لا تُقبل خصائص مجهولة، ولا يوجد تنفيذ شيفرة أو `eval`.
- يمكن تكرار المكونات المعلّمة بأنها غير فريدة، مثل Trigger Zone.

## الحفظ والتوافق

- أضيف حقل اختياري `components` إلى كائن المحرر.
- ملفات v1-v5 التي لا تحتوي على هذا الحقل تظل مقبولة.
- تُرفض بيانات المكوّنات غير المتوافقة أو الخارجة عن الحدود بدل تشغيلها أو تخزينها كبيانات تنفيذية.
- لا يزال إصدار الملف الخارجي v5، مع `schemaVersion: 1` للبنية المعيارية.

## الاختبارات المضافة

- وجود 12 تعريفًا ومعرفات فريدة.
- توافق المكونات مع أنواع الكائنات.
- القيم الافتراضية والتحقق من الحدود.
- إسقاط الخصائص غير المعروفة.
- قبول المكونات المتكررة المسموح بها.
- رفض المكوّن غير المتوافق والبيانات غير الآمنة.
- قبول ملف قديم بلا مكونات ورفض schemaVersion غير مدعوم.

## ما لم يُنفّذ بعد

- أصبحت واجهة إدارة المكونات موجودة داخل مفتش الكائن: قائمة توافق حسب نوع الكائن، وإضافة/حذف، وحقول مولدة من مخطط الخصائص.
- تُرفض إضافة مكوّن فريد مكرر، وتُسمح المكونات غير الفريدة مثل Trigger Zone بالتكرار.
- تُتحقق تغييرات الخصائص عبر السجل قبل اعتمادها، ثم تُحفظ تلقائيًا وتدخل سجل التراجع/الإعادة.
- تعرض كل بطاقة حالة ربطها: يعمل في المعاينة، مرتبط جزئيًا، أو إعداد محفوظ فقط؛ لتجنب الإيحاء بأن جميع المكونات منفذة.
- رُبطت مجموعة أساسية من المكونات بمحول التشغيل:
  - Movement يغيّر سرعة اللاعب/العدو.
  - Player Input يتيح تعطيل تحكم اللاعب.
  - Health يحدد الحد الأقصى للصحة.
  - Combat يضبط الضرر والمدى وفترة الانتظار.
  - Enemy Brain يحدد المطاردة أو الحراسة وسرعة العدو.
  - Collectible يحدد قيمة العنصر المجموع.
  - Animation يحدد نمط الحركة البصرية الموجود أصلًا.
- Health.current يحدد الصحة الابتدائية، وHealth.maximum يحدد الحد الأقصى الفعلي الذي يستخدمه نظام القتال وشريط الصحة.
- قيمة Collectible تدخل في إجمالي الجمع المطلوب بدل احتساب كل عنصر دائمًا بنقطة واحدة.
- مكونات Transform وVisual وCollider وTrigger Zone وAudio Emitter لا تزال بيانات إعدادات غير مكتملة الربط. كذلك Movement.maxSpeed وEnemy Brain.detectionRange وPlayer Input.scheme محفوظة حاليًا لكنها لا تغيّر سلوك المحرك بعد؛ لا ينبغي وصفها بأنها تعمل بالكامل.
- أضيفت اختبارات واجهة للحفظ والإضافة والحذف والتوافق، واختبار لمحول التشغيل الأساسي.
- تم تعديل GitHub Actions ليعمل أيضًا عند الدفع إلى فروع `stage-0/**`.
- اختبارات فعلية على هاتف Android.

## بوابة القبول

لا تُعتبر هذه الدفعة مجتازة حتى تظهر نتيجة ناجحة من GitHub Actions لأوامر `npm run typecheck` و`npm run test:e2e` و`npm run build`، ثم تُختبر واجهة الهاتف. إضافة الاختبارات إلى المستودع لا تعني أنها نجحت بالفعل.
