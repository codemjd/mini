# تنفيذ سجل المكونات — المرحلة الأولى

الحالة: تنفيذ أولي محفوظ على فرع العمل، ولم يُعلن جاهزًا للإنتاج قبل تشغيل الاختبارات.

## ما أُضيف

- سجل مركزي في `src/engine/component-registry.ts` يعرّف 12 مكوّنًا:
  Transform, Visual, Animation, Collider, Movement, Player Input, Health, Combat, Collectible, Enemy Brain, Trigger Zone, Audio Emitter.
- لكل مكوّن اسم عربي ووصف وفئة وأنواع كائنات متوافقة وخصائص افتراضية.
- تحقق مركزي من النوع والنطاق والخيارات واللون وطول النص.
- لا تُقبل خصائص مجهولة، ولا يوجد تنفيذ شيفرة أو `eval`.
- يمكن تكرار المكونات المعلّمة بأنها غير فريدة، مثل Trigger Zone.

## الحفظ والتوافق

- أضيف حقل اختياري `components` إلى كائن المحرر.
- ملفات v1-v5 التي لا تحتوي على هذا الحقل تظل مقبولة.
- تُرفض بيانات المكوّنات غير المتوافقة أو الخارجة عن الحدود بدل تشغيلها أو تخزينها كبيانات تنفيذية.
- لا يزال إصدار الملف الخارجي v5، مع `schemaVersion: 1` للبنية المعيارية.

## الاختبارات المضافة

- وجود 12 تعريفًا ومعرفات فريدة.
- توافق المكونات مع أنواع الكائنات.
- القيم الافتراضية والتحقق من الحدود.
- إسقاط الخصائص غير المعروفة.
- قبول المكونات المتكررة المسموح بها.
- رفض المكوّن غير المتوافق والبيانات غير الآمنة.
- قبول ملف قديم بلا مكونات ورفض schemaVersion غير مدعوم.

## ما لم يُنفّذ بعد

- واجهة مرئية لإضافة المكوّنات وإزالتها وتعديل خصائصها.
- ربط المكونات الجديدة بمحرك التشغيل الفعلي؛ السجل والحفظ والتحقق لا يعني أن كل مكوّن أصبح سلوكًا عاملًا داخل اللعبة.
- تشغيل TypeScript وPlaywright وVite Build على CI.
- اختبارات فعلية على هاتف Android.

## بوابة القبول

لا تُعتبر هذه الدفعة مكتملة حتى تنجح أوامر `npm run typecheck` و`npm run test:e2e` و`npm run build` في بيئة تشغيل موثوقة، ثم تُختبر واجهة الهاتف.
