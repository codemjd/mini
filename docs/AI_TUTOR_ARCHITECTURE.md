# معمارية المساعد الذكي — مواصفات أولية

## الهدف

مساعد يفهم مشروع Godot المفتوح، لا روبوت دردشة منفصلًا يجيب عن أسئلة عامة فقط.

## سياق يمكن للمساعد قراءته بموافقة المستخدم

- إصدار Godot.
- المشهد المفتوح وشجرة العقد.
- نوع العقدة المحددة وخصائصها الأساسية.
- رسائل الأخطاء والتحذيرات.
- السكربت الذي يختار المستخدم مشاركته.
- الدرس الحالي ومستوى التقدم.

لا تُرسل ملفات المشروع أو أسرار المستخدم تلقائيًا. يجب عرض ما سيُرسل قبل الإرسال.

## أوامر مقترحة

- اشرح العنصر المحدد.
- اشرح رسالة الخطأ.
- اقترح تعديلًا للسكربت.
- أنشئ عقدة أو مشهد تدريب.
- راجع الكود مقابل إصدار Godot المثبت.
- حوّل الطلب إلى خطوات صغيرة قابلة للتنفيذ.

## ضوابط التنفيذ

1. المساعد يقترح فرقًا واضحًا قبل الكتابة.
2. لا ينفذ تعديلات على ملفات المستخدم دون إذن واضح.
3. يحتفظ بنسخة قابلة للاسترجاع قبل التعديل.
4. يختبر السكربت أو المشهد بعد التعديل عندما تكون أداة الاختبار متاحة.
5. لا يزعم أن اللعبة اختُبرت إذا لم تُشغّل.
6. مفاتيح API تبقى في تخزين آمن خارج المستودع، ولا تكتب في ملفات المشروع العامة.

## تقسيم معماري

- Godot Mentor Dock: واجهة داخل المحرر.
- Project Context Collector: يجمع بيانات محدودة من المحرر.
- Lesson Engine: يتابع الدروس والمهام.
- AI Adapter: طبقة قابلة لتبديل مزود الذكاء الاصطناعي.
- Patch Planner: يعرض تغييرات الملفات قبل تطبيقها.
- Validation Runner: يشغّل فحوصات Godot ويعيد النتيجة للمساعد.

## الحالة

هذه وثيقة تصميم فقط. لم يتم تنفيذ اتصال AI أو إرسال بيانات خارج الجهاز في النموذج الحالي.
