# ورشة الشرارات Mini — النسخة الأولى / المسار A: المتوازن

الحالة: مسار تجريبي مستقل للمقارنة، وليس اعتمادًا نهائيًا.

## الهدف
امتلاك محرك شرارات فعلي مع الاستفادة من مكتبات متخصصة ناضجة، لتحقيق توازن بين الاستقلالية والجودة وسرعة التطوير.

## المعمارية
- Spark Core (ملكية المشروع): Project, Scene, Entity, Component, Event, Systems, Runtime.
- Renderer Adapter: PixiJS للرسم ثنائي الأبعاد.
- Physics Adapter: Planck.js للفيزياء والتصادمات ثنائية الأبعاد.
- Audio Adapter: Howler.js للصوت.
- Visual Logic: واجهة عقد مرئية؛ يمكن تقييم Rete.js، بينما صيغة الأحداث ومفسرها ملك لشرارات.
- Storage: IndexedDB خلف واجهة تخزين خاصة.
- Import/Export: صيغة مشروع شرارات موحدة، ثم HTML5 وZIP.
- Android: تقييم Capacitor بعد نجاح إصدار الويب.

## قواعد الاستقلال
1. لا تحفظ ملفات المستخدم بصيغ PixiJS أو Planck أو Rete.
2. لا تسمح لأي مكتبة خارجية بأن تصبح مالكة لنموذج المشروع أو نظام الأحداث.
3. كل مكتبة خلف Adapter قابل للاستبدال.
4. لا نشغّل محركي فيزياء على المشهد نفسه في وقت واحد.
5. لا نحذف Phaser من main خلال التجربة.

## نطاق النسخة الأولى
- إنشاء مشروع وحفظه وفتحه.
- مشهد واحد، كاميرا 2D، كائنات ومكونات أساسية.
- إضافة صورة/شكل، تحديد وسحب وتغيير الخصائص.
- تشغيل وإيقاف المعاينة.
- تصادمات أساسية، إدخال لمس ولوحة مفاتيح.
- تصدير مشروع شرارات JSON/ZIP.
- لا وعود بتصدير APK قبل إعداد واختبار مسار بناء Android.

## مراحل التنفيذ
1. تعريف مخطط Spark Project وواجهات Renderer/Physics/Audio.
2. بناء Spark Core واختبارات وحداته دون ربط واجهة المحرر.
3. ربط PixiJS وعرض مشهد تجريبي.
4. ربط Planck عبر Physics Adapter.
5. إضافة الإدخال والحفظ والاستيراد والتصدير.
6. بناء شريحة محرر قابلة للاستخدام على شاشة الهاتف.
7. قياس الأداء وحجم الحزمة واختبار المتصفح والهاتف.
8. تقييم Howler وRete وCapacitor كلٌّ في مرحلته.

## بوابات القبول
- يمكن تحميل مشروع محفوظ دون الاعتماد على حالة المحرر.
- يمكن تبديل Renderer تجريبيًا دون تغيير ملفات المشروع.
- اختبارات إنشاء/حذف الكائنات والمكونات والتصادمات ناجحة.
- لا أخطاء TypeScript أو build.
- المعاينة تعمل باللمس وبأحجام شاشة مختلفة.
- لا يتم دمج المسار في main قبل مراجعة النتائج.

## المخاطر
- تضخم نطاق Spark Core قبل وجود نموذج قابل للتجربة.
- اختلاف دورة حياة PixiJS عن نموذج المشروع.
- تعقيد مزامنة الفيزياء مع المعاينة.
- زيادة حجم الحزمة على الهواتف الضعيفة.

## قرار هذا المسار
هو المرشح الأساسي للمقارنة؛ لا يصبح المعتمد إلا بعد اجتياز نموذج رأسي صغير واختبارات الأداء.
