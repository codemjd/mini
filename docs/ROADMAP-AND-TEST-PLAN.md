# ورشة الشرارات Mini — خطة التحسين والاختبار

تاريخ التحديث: 2026-11-13

## الهدف القريب

تحويل محرر المشهد من نموذج أولي إلى أداة موثوقة على الهاتف، مع الحفاظ على بساطة الاستخدام وعدم إضافة أنظمة كبيرة قبل ثبات الأساس.

## ما أضيف في هذه الدفعة

- خلفية ساحة أغنى: تدرج لوني، توهجات زخرفية، حلقات بعيدة، نقاط ضوء، إطار داخلي وشبكة منفصلة قابلة للإخفاء.
- تحسين رسومات اللاعب والعدو والصندوق والمنصة والعملة باستخدام طبقات وتفاصيل وحدود وظلال.
- وضع معاينة أوضح بصريًا مع شارة تشغيل وشريط معلومات وعدّاد للعملات.
- حفظ نسخة مؤقتة من عناصر المشهد عند بدء المعاينة، ثم استعادتها عند الإيقاف؛ جمع العملة أثناء الاختبار لا يحذفها من مشروع التحرير.
- تحسين إبراز وضع المعاينة وعناصر التحكم باللمس على الشاشات الصغيرة.
- إضافة اختبار آلي يتحقق من جمع العملة مؤقتًا واستعادة المشهد.

## خطة التحسين حسب الأولوية

### P0 — الثبات وتجربة الهاتف
1. التحقق من تشغيل المحرر على عرض 320px و360px و390px وبدقة لوحية.
2. التأكد من عدم تداخل شريط الأزرار مع عنوان المشروع.
3. اختبار المعاينة باللمس والكيبورد، وإيقافها والعودة للتحرير.
4. التأكد من استعادة العناصر ومواقعها بعد المعاينة.
5. اختبار الحفظ وإعادة التحميل وتصدير JSON.

**معيار القبول:** لا أخطاء JavaScript، ولا فقدان لعناصر المشهد في دورة تحرير/معاينة/إيقاف/حفظ.

### P1 — أدوات التحرير الأساسية
1. إضافة تراجع/إعادة (Undo/Redo).
2. إضافة استيراد مشروع JSON مع التحقق من البيانات ورسائل أخطاء واضحة.
3. جعل الحجم واللون قابلين للتعديل لجميع العناصر، وليس الشخصيات فقط.
4. إضافة محاذاة للشبكة، نسخ متعدد، وقفل العناصر.
5. تحسين إدارة أسماء العناصر وترتيبها.

**معيار القبول:** يستطيع المستخدم إنشاء مشهد، حفظه، استيراده، وتعديل كل نوع عنصر دون تلف البيانات.

### P2 — مكتبة الأصول
1. مكتبة داخلية مقسمة إلى شخصيات وأعداء وبيئات وعناصر ومؤثرات.
2. معاينة الأصل قبل إضافته.
3. أصول متناسقة بصريًا مع حقوق استخدام واضحة.
4. تحميل تدريجي للأصول لتقليل استهلاك الهاتف.

**معيار القبول:** إضافة أصل من المكتبة إلى المشهد دون الاعتماد على روابط خارجية وقت التشغيل.

### P3 — بناء الألعاب
1. محرر أحداث مرئي (عند النقر، عند الاصطدام، عند جمع عنصر).
2. نظام تصادمات ومناطق تفعيل.
3. كاميرا ومراحل متعددة.
4. واجهة لعب قابلة للتخصيص.
5. تصدير HTML5/ZIP قابل للتشغيل، ثم دراسة APK عبر بناء سحابي.

**معيار القبول:** إنشاء لعبة صغيرة قابلة للعب والتصدير من دون كتابة كود يدوي.

## خطة الاختبار

| المجال | السيناريو | النتيجة المطلوبة |
|---|---|---|
| الإقلاع | فتح الصفحة أول مرة | ظهور المحرر ولوحة المشهد دون أخطاء |
| العناصر | إضافة الأنواع الخمسة | ظهور كل عنصر في القائمة والمشهد |
| التحديد | اختيار عنصر من القائمة والمشهد | تحديث الخصائص الصحيحة |
| التحريك | سحب عنصر وتعديل X/Y | تطابق موضعه المرئي مع القيم |
| النسخ والحذف | نسخ عنصر ثم حذفه | العدد والقائمة صحيحان |
| المعاينة | بدء وإيقاف المعاينة | تبديل الواجهة واستعادة وضع التحرير |
| الحركة | أسهم وWASD وأزرار اللمس | حركة سلسة ضمن حدود الساحة |
| العملات | المرور فوق عملة | زيادة العداد وإخفاؤها أثناء المعاينة |
| الاستعادة | إيقاف المعاينة بعد جمع عملة | عودة العملة وباقي العناصر كما كانت |
| الحفظ | حفظ ثم إعادة تحميل | استعادة العناصر والخصائص |
| التصدير | تنزيل JSON | ملف صالح يحوي بيانات المشروع |
| الاستجابة | 320–900px | عدم اختفاء الأزرار أو تداخل اللوحات |
| المتانة | مشروع محفوظ غير صالح | رسالة آمنة دون انهيار التطبيق |

## بوابات الإصدار

- **بوابة البناء:** TypeScript وVite build ينجحان.
- **بوابة الاختبارات:** Playwright ينجح على Chromium المكتبي والهاتف.
- **بوابة النشر:** GitHub Pages workflow يكتمل بنجاح لنفس commit الذي اجتاز الاختبارات.
- **بوابة الاستخدام:** تجربة يدوية على هاتف Android فعلي؛ الاختبار الآلي لا يغني عنها.

## حدود النسخة الحالية

المعاينة ما زالت نموذج لعب بسيطًا: حركة لاعب وجمع عملات. لا يوجد حتى الآن تصادم كامل أو قتال أو ذكاء أعداء أو نظام مراحل أو تصدير لعبة قابلة للتثبيت. ملف JSON هو بيانات مشروع فقط، وليس APK.
