# ورشة الشرارات Mini — خارطة الطريق وخطة الجودة

آخر تحديث: 2026-11-14  
الإصدار الحالي في المستودع: 0.4 — رحلة البلورات

## ما أُنجز في الإصدار 0.4

- إنشاء ساحة «جزيرة البلورات» بخلفية طبيعية متعددة الطبقات مرسومة داخل Phaser.
- إعادة تصميم المستكشف وحارس الوحل والبلورات والصناديق والمنصات برسوم متجهة وتفاصيل وظلال.
- إضافة لعبة بداية قابلة للمعاينة: بطل، حارس يلاحق اللاعب، أربع بلورات، هجوم قريب، ورسالة عند جمع البلورات كلها.
- تفعيل أزرار اللمس على الهاتف، والأسهم وWASD والهجوم على الكمبيوتر.
- استعادة حالة التحرير عند إيقاف المعاينة؛ جمع البلورات في المعاينة لا يُحذف من المشروع المحفوظ.
- إضافة مساعد عربي حتمي في src/local-assistant.ts؛ يفسّر قائمة أوامر معروفة ويحوّلها إلى إجراءات محددة، دون اتصال أو نموذج AI.
- دعم تجهيز لعبة البداية، وإضافة عناصر وبلورات، وتعديل سرعة البطل وضرره، وإضعاف العدو أو تقويته، وتغيير الألوان، والنسخ والحذف والتراجع والإعادة.
- تغيير مفتاح التخزين المحلي حتى لا يخلط الإصدار الجديد تلقائيًا مع حفظ النسخة التجريبية السابقة.
- إضافة اختبارات Playwright لبدء التطبيق، وأوامر المساعد، وتعديل البطل، وتشغيل المعاينة واستعادة المشهد، وقياس التمرير الأفقي على شاشة الهاتف.
- إضافة مسار GitHub Actions لفحص TypeScript والبناء واختبارات Chromium المكتبية والهاتفية.

## حالة التحقق

تمت إضافة الاختبارات ومسار CI إلى المستودع، لكن لا تُعد هذه الاختبارات ناجحة لمجرد وجود ملفاتها. يجب انتظار نتيجة GitHub Actions والتحقق من نجاح كل خطوة. كما أن محاكاة الهاتف في Playwright لا تغني عن تجربة اللمس والأداء على هاتف Android فعلي.

## الأولويات التالية

### P0 — إثبات الثبات على الهاتف
- التحقق من نجاح Quality checks وPublish web preview على آخر commit.
- إصلاح أي خطأ TypeScript أو بناء أو اختبار يظهر في CI.
- تجربة السحب واللمس والمعاينة على هاتف Android فعلي.
- التأكد من عدم فقد المشروع عند الحفظ وإعادة فتح الصفحة.
- التحقق من عدم تجاوز الواجهة عرض 320 و360 و390 و430 بكسل.

**معيار القبول:** نجاح البناء والاختبارات الآلية، ثم اجتياز تجربة هاتف فعلية دون تعطل أو تداخل مؤثر.

### P1 — ترقية جودة الرسومات
- إنشاء نظام أصول حقيقي يدعم صور PNG وWebP وSprite Sheets.
- تجهيز شخصيات ذات حالات حركة واضحة: خمول، مشي، هجوم، إصابة.
- إضافة مؤثرات صوتية وبصرية قابلة للتحكم.
- بناء مكتبة صغيرة منتقاة من أصول مرخصة بوضوح، مع معاينة قبل الإضافة.
- دعم خلفيات وطبقات بيئية قابلة للتعديل بدل حصر البيئة في رسم برمجي ثابت.

**معيار القبول:** يمكن بناء لعبة قصيرة بمظهر متسق باستخدام أصول مدمجة قابلة لإعادة الاستخدام، لا أشكال المشهد الافتراضي وحدها.

### P2 — أدوات صناعة لعبة مصغرة
- إضافة أنواع ألعاب بداية أخرى، مع الحفاظ على نموذج مشروع واحد.
- إضافة مناطق تصادم ومناطق التقاط وتفاعلات يمكن ضبطها.
- فصل خصائص الكائن ومظهره وسلوكه عن كود العرض.
- إضافة نظام أحداث مرئي صغير: عند البدء، عند اللمس، عند التصادم، عند جمع عنصر.
- جعل المساعد المحلي قابلًا للتوسعة عبر أوامر موصوفة ومختبرة، مع رسائل واضحة عندما لا يفهم الأمر.

**معيار القبول:** يستطيع المبتدئ تركيب لعبة قصيرة من قالب وعناصر وقواعد واضحة، دون كتابة كود.

### P3 — محرر ومشاريع
- مشاهد متعددة وأسماء وترتيب.
- تحديد متعدد ونسخ ولصق ومحاذاة وتوزيع.
- خصائص الدوران والشفافية والأبعاد المنفصلة.
- سجل تاريخ أكثر دقة وتجميع تغييرات السحب.
- حفظ تلقائي محمي ونسخ احتياطية وإدارة أصول المشروع.

**معيار القبول:** تحرير مشروع يضم عدة مشاهد وعشرات العناصر على الهاتف دون فقد أو بطء غير مقبول.

### P4 — التصدير
- حزمة HTML5 مستقلة تعمل خارج المحرر.
- تصدير ZIP للمشروع مع الأصول.
- بناء APK عبر بيئة بناء سحابية.
- التحقق من التثبيت والتشغيل وتوقيع التطبيق قبل إعلان جاهزية APK.

**معيار القبول:** لا يُعلن أي نوع تصدير جاهزًا قبل إنتاج ملف حقيقي واختباره خارج الورشة.

## بوابات الإصدار

1. npm run typecheck ينجح.
2. npm run build ينتج dist/index.html.
3. npm run test:e2e ينجح على Chromium المكتبي ومحاكاة Pixel 7.
4. GitHub Pages ينشر نفس commit الذي اجتاز البناء.
5. تجربة يدوية على هاتف Android للتحقق من اللمس والأداء.

## حدود الإصدار الحالي

الإصدار 0.4 هو شريحة لعب ومحرر مشهد أولي، وليس محركًا مكتملًا. الرسومات الحالية مرسومة برمجيًا داخل Phaser وليست مكتبة شخصيات أو Sprite Sheets فعلية. المساعد محرك قواعد محدود، وليس ذكاءً اصطناعيًا عامًا. لا توجد بعد مشاهد متعددة أو محرر أحداث مرئي أو نظام تصادم متكامل أو تصدير HTML5/ZIP أو APK. ملف JSON يحفظ بيانات المشروع فقط.
